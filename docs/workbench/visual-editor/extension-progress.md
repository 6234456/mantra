## 兼容性结论的使用方式

全工作簿清单和真实 Template Engine 执行是两份证据，应一起阅读。现有证明使用简单公式案例和
`actuals-vs-baseline` 的明确基准／输入修改案例。受源绑定数值的限定比较与源业务 finding 的保留，
只支持报告中的 `scopedNumericalInputRecalculationProofPassed` 范围。

完整工作簿兼容保持 false。审计辅助页使用的 `EXACT`、`ISBLANK`、`ISLOGICAL`、`ISTEXT` 等函数，
以及 `ROUND` 的负数／中点舍入和 binary64 精度，都有具体反例。函数错误数为零或导入成功不能消除
这些差异。审计工具的 `proof --require-compatible` 应在完成不兼容报告后返回失败状态，防止把
“成功生成审计证据”当作“可以发布兼容模板”。本轮没有模板目录登记或 Template Engine 发布成功。

证据记录 Template Engine 源提交和模块摘要，而不引用另一个会话的未提交工作区。最终记录应保留
产物、源映射、依赖锁及重跑命令；源文件或依赖发生改变后重新生成证明。

## 契约缺口的当前状态

新的模板预览端点推进 **G-A4／G-A14 的只读候选切片**：原文编辑和示例输入可以在同一候选下产生
真实 Paper 与 Explain；全部参与修订与序号供客户端判断结果是否当前。现有模拟扫描器仍不代表
正式的属性 owner API；文档句柄不能当作语义属性句柄或任意写入路径。

G-A1–G-A3 的正式 owner、Outline 和语义最小补丁，G-A5 的模板语言服务，G-A6–G-A7 的源历史／提交，
G-A8 fork、G-A9 样式规则来源、G-A10–G-A11 构建记录／发布，以及正式恢复、模板外部事件和无效
草稿 owner 的其余部分，仍按各自契约推进。独立兼容性审计文件也不是已实现的构建／发布服务。

**D-A1 多文档保存原子性仍未实现。** schema/layout 的内存覆盖不涉及文件提交；原型模拟保存与备份
恢复都不改变这一点。下一步先定义实际文件提交的失败语义与恢复行为，再接入提交 API 和用户界面。
本轮继续预览、导入、证据和工具链工作，不因 D-A1 尚未完成而要求用户提前拍板。
