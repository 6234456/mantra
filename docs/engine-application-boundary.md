# 引擎与领域应用的职责契约

> 当前实现与下一步抽取依据。`examples/` 是领域应用的验收原型，不参与引擎库发布。

## 依赖方向

```text
用户 case ──▶ 领域应用 schema / 输入契约 ──▶ mantra-core ──▶ CalculationResult
                  ▲                             │                    ├─▶ mantra-render + layout ─▶ HTML / Text
             可选数据适配器                       ▼                    └─▶ mantra-excel + layout  ─▶ XLSX
                                              Normein
```

领域应用使用引擎的公开 DSL 与 API；用户 case 使用应用公开的输入、参数和扩展点。`mantra-core` 不认识 ESt、IAS 36、SAP CO、CGU、工单或产品；应用不复制维度对齐、精确分摊、依赖排序、舍入和审计逻辑。数据适配器只把外部数据转成应用声明的输入，不在读取阶段暗中计算业务结果。

## 谁定义什么

| 内容 | 引擎 | 领域应用 | 用户案例 / 版式 |
| --- | --- | --- | --- |
| DSL 语法、类型、维度、依赖、错误与追溯 | 定义并执行 | 按公开接口组合 | 调用，不配置内部求值顺序 |
| `section`、`line`、`total`、`choice`、`slot`、`formula-slot` | 定义统一语义 | 组成业务流程并声明可扩展处 | 仅向开放的 `slot` 添加内容或向 `formula-slot` 绑定公式 |
| 表格、成员关系、跨维度聚合 | 检查成员唯一性、父键与表格外键，并提供 `dim/rollup`；XLSX 使用同一父关系生成公式 | 用 `:parent`、`:references` 声明关系及业务汇总口径 | 填写记录与关系键 |
| 按权重分摊、舍入、加权平均的算术 | 提供与业务名词无关的原语及精确合计约束 | 选择分配对象、权重来源、口径和精度 | 提供权重、数量与应用允许调整的参数 |
| 标准与实际、减值、所得税等业务规则 | 不定义 | 定义计算公式、科目映射、业务校验与版本 | 提供事实数据及允许的方案选择 |
| 输出 | 定义受限列、表格、格式、审计呈现及 `class`/`style` 样式契约 | 给计算项标注 `:class`，提供默认 layout 样式 | 在允许范围内选版式和定义 `(style {选择器} {样式声明})`；不能改变计算值 |

`schema.mantra` 是当前领域应用的可执行定义，`case.mantra` 是用户实例。引擎已校验未知输入、未知参数、未知扩展槽、公式绑定和输入类型；案例写了 `:schema` 时，也必须与加载的方案 ID 一致。省略 `:schema` 仍可用于临时案例。领域应用应把 `:schema` 视为正式案例的必填约定。

## 原语上提规则

只有满足下面全部条件，才把逻辑从应用方案提升到引擎：

1. **语义跨领域不变**：参数和键名可以变，算法的数学含义与异常条件不变。例如“按非负权重精确分摊到分位”可以上提；“总部资产按账面价值分摊”属于 IAS 36 应用。
2. **输入输出可类型化**：声明数值、键、维度和空值规则；引擎能在计算前验证或在计算时给出稳定诊断。
3. **可追溯、可复算**：同一原语在核心求值、Text/HTML 与 XLSX 中有相同口径；不能静默退化成看似可重算的固定值。
4. **不带业务词汇**：通用原语使用 `dimension`、`relation`、`allocation`、`measure` 等概念。税率、CGU、成本要素、工单等名称只出现在应用方案。

已经上提的能力包括 `alloc/pro-rata`、`dim/sum`、Staffel `total`、维度对齐、条件继承、`choice`、精确十进制和审计轨迹。核心求值与 XLSX 导出共用条件成员组合规则。简单算术和 `map`/`sum` 直接使用 Normein；引擎无需为每个业务公式包一层同义函数。

## 两个应用的边界实例

| 计算步骤 | 引擎提供 | 应用定义 | 用户提供 |
| --- | --- | --- | --- |
| IAS 36 总部资产分摊 | 维度、权重映射、精确分摊、条件继承 | CGU、资产类别、减值顺序、可收回金额与测试口径 | 资产金额、CGU 数据、允许的加权方法及参数 |
| SAP CO 风格成本归集 | 表格与维度、按键分摊、求和、精确舍入、追溯 | 初级/次级成本分类、工单→产品关系、标准/实际成本及差异公式 | 费用流水、工单、产品、完工数量、分配基数、标准成本 |

用户不需要选择“条件跨维度如何生效”或“哪些节点先算”；这属于引擎语义。用户需要看见应用允许调整的业务加权口径及其输入，并能从审计轨迹核对结果。

## 下一步按依赖顺序细化

1. **受控公式接口的后续细化**：已实现 `formula-slot` 与 `bind`，复用原行的结果类型、维度、舍入和依赖校验；应用可用 `:uses` 限制绑定公式引用的输入或计算行。IAS 36 权重行已有自定义案例。后续可细化字段级访问和可调用函数的许可范围。
2. **关系式汇总的后续细化**：应用可在表格维度声明 `:parent` 和 `:parent-key`，也可在普通表格输入声明 `:references {:列 维度}`。引擎检查父成员、成员主键唯一性和非空外键是否指向活动成员，并提供 `relation_<维度>` 映射与 `dim/rollup`。SAP 案例的工单→产品汇总及费用流水→工单校验已使用这些原语。条件性必填（如“直接费用必须有工单”）仍需应用声明业务校验口径。
3. **度量聚合语义**：金额、数量可求和，单位成本不能直接相加。引擎现在将 `:aggregate false` 或 `:aggregate :none` 解析为度量规则，`NodeResult.crossTotal()` 对此返回 `null`，底稿与 XLSX 均不生成横向合计。需要跨成员的单位成本时，由应用显式定义“总成本 / 总数量”公式。未来若需要通用比率聚合，可在引擎中加入指定分子和分母的规则。
4. **导出一致性**：XLSX 公式翻译器支持当前案例使用的单参数 `map(fn [row] …)`，表格行字段直接引用可编辑的输入单元格。SAP 案例的来源分类、按工单归集、产品汇总和对账均可重算，测试确认没有固定值回退。更广泛的高阶函数形式仍需按实际需求逐项定义语义与导出能力。
5. **稳定的结果接口**：目前 `CalculationResult` 暴露 `CalculationPlan`，渲染和 XLSX 模块读取具体顶点类型。应抽出只读的计算结构与结果视图，让应用和输出端依赖稳定契约；`Planner`、编译表达式和执行缓存留在引擎内部。
6. **应用版本**：正式应用除方案 ID 外还应声明语义版本，并记录案例使用的版本。方案的业务公式或输入含义变化时，旧案例必须明确迁移或继续使用旧版本，不能被同名新方案静默重算。

每完成一项，增加一个引擎原语测试和至少两个不同领域的应用验收；应用案例继续只通过 `Mantra` / `Render` / `ExcelExport` 公开接口使用引擎。
