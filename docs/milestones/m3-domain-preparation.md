> 依据：[路线图 M3](../roadmap.md#M3-跨案例延续与有界迭代v04)、§2.4、R7

本文为 M3 工作包提供独立金额来源、展示范围与链接验收需求。它不锁定 links DSL，

## 1. 来源与年份

2024 → 2025 的案例必须使用相应年度的规则。当前合并法条可能包含以后年度的修订，不能
仅凭检索日期，把当前文本的全部参数套用到历史年度。金额来源应在 M3 开工时先冻结，
然后实现；法律参数和应用简化分别记录，不能让独立脚本跟随引擎输出修改。

| 选定规则 | 已查阅的一手来源 | 本应用的用途 |
| --- | --- | --- |
| §10d EStG | BMF [EStH 2024 §10d](https://esth.bundesfinanzministerium.de/esth/2024/A-Einkommensteuergesetz/II-Einkommen-2-24b/5-Sonderausgaben-10-10g/Paragraf-10d/inhalt.html)、[EStH 2025 §10d](https://esth.bundesfinanzministerium.de/esth/2025/A-Einkommensteuergesetz/II-Einkommen-2-24b/5-Sonderausgaben-10-10g/Paragraf-10d/inhalt.html) | 年末剩余亏损、次年扣除、超过单人 100 万欧元门槛部分的 70% 限额；展示明确放弃亏损回溯 |

2024/2025 的 §10d 规则有单人 100 万欧元、共同申报 200 万欧元的基础额度；超过部分为
70%。不能将它误用于 Gewerbeverlust；后者 [§10a GewStG](https://www.gesetze-im-internet.de/gewstg/__10a.html)
另有口径。本轮 GewSt 展示不计算 Gewerbeverlust，两个税种的亏损余额也不能互相链接。

## 2. 展示范围与版本

新增 `apps/de-gewst` 只展示一个自然人独资企业、一个日历年度、一个虚构市镇。不处理
合伙分配、Organschaft、跨市镇 Zerlegung、免税主体、特殊车辆租金优惠、短纳税期、
境外项目、全部 §8 加回项目或 §9 减除。输入的费用均已在利润中扣除且符合所选类别；
分类与资格是案例给定事实，不由引擎识别。每项简化需要英文 README 和方案内注释。

`apps/de-est` 的现有 `de.est/2025` 版本 `2025.2`：

- `verlustabzug` 目前仅取亏损余额与正 Gesamtbetrag der Einkünfte 的较小值，注释明确未计算
  §10d 基础额度和最低税基。
- `ermaessigung-35` 未计算正营业收入占全部正收入的归属上限。
- `gewst-gezahlt` 的现有名字指“已支付”；§35 的金额上限实际指应缴 GewSt。M3 新案例不得
  将现金支付时间当作法定抵减口径。

建议保留旧方案文件和旧案例绑定，新增显式版本供链接展示使用。目录安排与解析器支持在
M3 工作包锁定；R7 的旧版本并存原则已经确定，不应覆盖旧方案后假称旧案例未迁移。
不必在 M3 提前交付 M4 的完整方案包、版本仓库或迁移 UI。

建议 2024 来源是同一应用内的**专门亏损余额方案**，标题明确只计算 §10d 结转，不宣称
计算完整 2024 所得税。它按 2024 自身版本独立计算；2025 消费端使用显式的新 ESt 版本。
这样无需把 2025 税率偷偷用于 2024，也无需为一个余额来源重建全部旧年度申报表。

新 ESt 版本应补齐本轮选定的 §10d 限额与 §35 归属上限。消费端主案例为单人、无儿童、
无其他收入及税收抵减，既有其他领域简化仍照实保留。共同申报基础额度可以作为单独
金额边界核对；涉及亏损归属、配偶变化与分配的跨年链接先不纳入展示。

## 3. §10d：独立跨年事实与金额

主链同一虚构纳税人 `Demo-A`，币种 EUR，显式放弃 2024 亏损回溯。给定的负收入已经完成
本年度收入间抵销，没有特殊亏损限制类别。正负总额不包含 Sonderausgaben 引起的缺口。

| 项目 | 2024 来源 | 2025 消费端 |
| --- | ---: | ---: |
| 年初通用亏损余额 | 5,000 | 链接 2024 年末 |
| 本年未抵销负收入 | 40,000 | 0 |
| 本年正收入总额 P | 0 | 32,000 |
| 亏损回溯 | 0，明确选择放弃 | 0 |
| 本年亏损前抵扣 | 0 | 32,000 |
| 年末通用亏损余额 | 45,000 | 13,000 |

在上述范围内，独立账本公式为：

```text
P = max(本年可用正收入总额, 0)
cap = min(P, sockel) + 0.70 × max(P - sockel, 0)
used = min(opening_loss, cap)
closing_loss = opening_loss + eligible_new_loss - used - selected_carryback
```

没有正收入时 `used = 0`；年末余额不能由净应税收入或所得税直接反推。2025 链接到现有
`verlustvortrag` 输入，新版本还需要独立可寻址的 `verbleibender-verlustvortrag` 输出作为下一年
来源。余额是存量，新增和使用是流量；跨案例链接没有再次累加上一年的存量。

| 边界 / 修订 | 事实 | 独立预期 |
| --- | --- | --- |
| 来源修订 | 2024 新亏损由 40,000 改为 50,000 | 来源 closing 55,000；2025 opening 55,000、used 32,000、closing 23,000；下游修订变化 |
| 余额恰好用完 | 2024 新亏损 27,000，加期初 5,000 | closing 32,000；2025 closing 0，真实链接零保持 Provided 来源 |
| 显式零来源 | 2024 opening/new loss 都为 0 | 2025 opening 0，不能视作链接缺失或应用本地默认 |
| 无正收入 | opening 45,000，P=0 | used 0、closing 45,000 |
| 单人门槛 | opening 3,000,000，P=2,000,000 | cap/used 1,700,000，closing 1,300,000，亏损后正收入 300,000 |
| 基础额度两侧 | opening 足够，P=999,999 / 1,000,000 / 1,000,010 | used 999,999 / 1,000,000 / 1,000,007；最后一项留下正收入 3 |
| 共同申报额度，仅金额核对 | opening 5,000,000，P=3,000,000，sockel=2,000,000 | used 2,700,000、closing 2,300,000；不宣称覆盖配偶亏损归属 |
| 缺失 / 不适用来源 | 来源不存在，或指定输出为 nil / 非数字 | 诊断保留，不能转换为零、沿用旧缓存或静默读取其他节点 |

所有展示事实先选整欧元，使法定报表层的余额取整规则不会与跨案例能力混淆。另行加入
分币边界前，应锁定余额和抵扣金额各自的法律舍入规则，不能套用显示精度代替法律规则。

## 4. GewSt → ESt：独立跨方案事实与金额

虚构独资企业 `Demo-Trade`，2025；`profit=120000` 已扣除下表费用。无其他加回或减除，
无 Gewerbeverlust，且没有需要特殊租金优惠的资产。

| §8 Nr. 1 项目 | 实际已扣费用 | 纳入加权合计 |
| --- | ---: | ---: |
| 债务费用 | 150,000 | 150,000 |
| 普通动产租金 | 100,000 | 20,000 |
| 不动产租金 | 100,000 | 50,000 |
| 普通限期许可费用 | 40,000 | 10,000 |
| 合计 | 390,000 | 230,000 |

独立计算：加回 `(230000 - 200000) × 0.25 = 7500`；Gewerbeertrag `127500`；
百欧元取整后仍为 `127500`；扣除 `24500` 后税基 `103000`；Messbetrag `3605.00`。
首轮应用参数应明确存 Hebesatz 为百分数 `300/400/450` 或比例 `3/4/4.5` 的其中一种，
导入模板、XLSX 和 README 使用相同单位，不依靠引擎猜测。

| 虚构 Hebesatz | 应缴 GewSt | 四倍 Messbetrag | §35 抵减主案例 |
| --- | ---: | ---: | ---: |
| 300% | 10,815.00 | 14,420.00 | 10,815.00，应缴 GewSt 上限生效 |
| 400% | 14,420.00 | 14,420.00 | 14,420.00，两上限相等 |
| 450% | 16,222.50 | 14,420.00 | 14,420.00，四倍 Messbetrag 上限生效 |

消费端 `Person A` 的营业收入为利润 `120000`，不是 GewSt 的 `127500`；其他收入与真实
特殊扣除为零，仅采用现有方案的单人 Sonderausgaben-Pauschbetrag `36`。应税收入
`119964`，2025 tarifliche ESt `floor(0.42 × 119964 - 10911.92) = 39472`；正营业收入
占全部正收入的比率为 1，归属上限为 `39472`。抵减后的 ESt 主金额分别为 `28657`、
`25052`、`25052`。这些金额只准备该选定 ESt 计算链；Soli 等其他输出仍需独立脚本按原
应用口径逐项复算，不能据主金额声称完整验收。

建议两个真实链接分别传递：

```text
GewSt 税额案例#messbetrag             → ESt input gewst-messbetrag, coord [:A]
GewSt 税额案例#gewerbesteuer          → ESt 应缴 GewSt 输入, coord [:A]
```

其中第二个目标的兼容命名留待版本方案决定：可以保留旧节点 ID 并修正新版本标签，或在
新版本改名并明确迁移；不能把计算出的“应缴”金额写成现金“已支付”的事实。利润是否
同时链接到 ESt `gewinn-gewerbe` 是可选扩展；首轮让双方同用独立事实，并做对账，避免
新增第三条链接掩盖输入/field 目标类型的契约问题。

| 边界 | 独立预期或验收目的 |
| --- | --- |
| 加权融资额 199,999 / 200,000 / 200,001 | 加回 0 / 0 / 0.25；门槛应用于加权合计，不是原始总费用，也不能把全部合计再乘 25% |
| 原 Gewerbeertrag 24,499.99 / 24,500 / 24,599.99 / 24,600 | 百欧元向下取整 24,400 / 24,500 / 24,500 / 24,600；Messbetrag 0 / 0 / 0 / 3.50；400% 税额 0 / 0 / 0 / 14.00 |
| 混合正收入，归属上限生效 | 营业利润 30,000、自雇正收入 170,000、债务费用 500,000；加回 75,000，Gewerbeertrag 105,000、Messbetrag 2,817.50、四倍 11,270；2025 tarifliche ESt 73,072，正收入比率 0.15、未舍入归属上限 10,960.80 |
| 无正营业收入 / 全部正收入为零 | 比率与抵减的零分母处理显式；无 NaN，无伪造 100% 归属，不用一般 ratio 警告掩盖税务分支 |
| 负费用、缺分类或不支持主体 | 应用 BUSINESS 诊断与已算数值并存，按照 R6 可保存；禁止静默改为支持的类别 |

## 5. 独立来源文件与验收计划

开工后每个应用的 `verify_expected.py` 使用 Python 标准库 Decimal，高精度工作上下文，
字符串金额，显式法律舍入；不导入 Mantra，不读取引擎值生成 expected，也不照抄 DSL
表达式树。比例上限另用 Fraction 作小范围交叉检查；主数字先人工列出后由脚本验证。

建议冻结以下文件，再写 schema/cases：

- `fixtures/*.json`：虚构原始事实、年度、纳税人/企业标识、适用性与明确的回溯选择。
- `parameters.json`：数值、适用年份、法条链接、检查日期；法规口径与演示简化分开。
- `data/*.csv` 与 typed import templates：费用分类、个人输入、源案例选择；真实零、false、
  空白三者分别保留。
- `references/*-values.json`：每个选定中间节点、源案例 closing、消费端 opening 与税额；
  `*-summary.json`：限额/余额恒等式和预期 BUSINESS diagnostics。
- `source-manifest.json`：事实、脚本、参数和 refs 的 SHA-256；原始法条只记录链接与年度，
  不以一份日后改变的网页代替已冻结金额事实。
- 英文 README：Demonstration only 声明、支持范围、简化、来源、运行方式与链接修订示例。

CI 仍须渲染全部主案例与边界的 HTML、Text、XLSX，逐地址比对每个金额，应用只调用公开
API。XLSX 链接值作为本次计算的输入快照，并带来源案例/节点/坐标/方案版本/修订批注；
本工作簿内公式照常重算，跨案例重新解析由 CLI/工作台执行。工作台无需税务特例。

链接特有验收至少包括：两个源案例的相对路径解析、明确节点/坐标、期望方案 id/版本
不匹配、不存在的输入/输出、scalar 到 person 坐标映射、真实零/false/nil、重复目标和
本地输入冲突、跨案例环、深度与运行预算、源 schema/params/layout/data 参与修订、
源 BUSINESS 错误的可见传播，以及来源修订后 SSE 与 Explain 的过期处理。
类型错误、不可解析源与循环属于技术失败；已可计算但业务检查失败遵守 R6，不应默默
丢掉源诊断或把来源标成可信成功。

有界迭代的金额来源可以使用领域中性的奖金闭式算例：税前/奖金前利润 `100000`，奖金
率 `0.10`，公式 `bonus = 0.10 × (100000 - bonus)`；精确解 `100000 / 11`，若最后
才舍入为 cents，结果 `9090.91`。每轮是否舍入、初值、收敛精度与最大迭代数由内核契约
锁定后再生成 expected；不拿该闭式解假称所有停止规则等价。未收敛与预算用通用测试。

## 6. 工作包需锁定的架构选择

路线级 R7 无需重新提问；以下是开工前的具体契约事项，默认建议已给出：

1. **链接目标类型与冲突。** 允许已有可编辑 numeric input 和 field，但只允许显式目标
   坐标；同目标两来源、或同时存在本地值和链接值，建议拒绝并给确定诊断，避免隐式覆盖。
2. **nil 与错误源。** 数字零是已提供值；nil 保持未提供/未定义。源业务错误继续提供忠实
   金额并携带来源诊断；技术错误不输出伪零，不能借旧缓存继续算成功。
3. **版本绑定。** 先用不同 schema 文件路径和声明版本展示共存，期望 id/version 精确
   验证；完整版本解析与迁移产品留 M4。2024 亏损专用方案的独立 ID/版本在工作包确定。
4. **Explain 地址。** 案例身份、scheme id/version、节点、多维坐标与 revision 都参与
   跨案例来源；链接源本身按自身参数独立计算，不能用消费端的 2025 参数重算 2024。
5. **有限金额范围。** 首轮锁定独资企业和单人跨年主链；配偶归属、全部税务类别和真实
   城市税率不是引擎原语的前置条件。若维护者要求扩展主体，再先补独立来源。

本次准备实际完成：查阅上述一手来源；用独立 Decimal 临时计算核对主 GewSt 三税率、
跨年余额、最低税基门槛及 Freibetrag 边界。尚未建立 M3 源脚本/manifest、DSL、链接 API、
golden、XLSX 或工作台验收，不能将本文列为 M3 完成记录。
