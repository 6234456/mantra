## 2. 实施契约

### 2.1 编译与类型化嵌入

`Mantra.compile` 返回可共享的不可变编译模板，模板携带方案身份、扩展身份、编译时参数类型、
内核身份及来源位置。输入可直接使用 `CaseData`/`Value`，不需要生成 DSL 文本。
模板在编译时检查公式与宿主结构；输入值、成员域及业务校验仍在每个实际案例中检查。
同样的编译模板可以接受不同案例 ID；输出的 case、参数层、来源和诊断必须属于当前案例。
参数类型、函数、扩展和公式绑定不兼容时显式拒绝模板复用，不能悄悄编译一个不同模板。

每次独立求值及读取都有新的运行控制；审计请求采用 FULL，普通计算和批量采用 VALUE_ONLY。
编译模板没有可变求值会话。会话由打开它的线程使用和关闭；结果快照可传给其他线程。
每个 worker 拥有独立会话；首版批量采用顺序、流式消费，默认不并行。
批量回调在结果已经脱离可变运行时后执行；取消后不回调未完成案例。技术失败没有旧值替补，
非阻断 BUSINESS 诊断继续随当前值输出。批次有独立数量上限和总期限，每个案例仍受 M3 预算保护。

### 2.2 方案包

首版已实现 `manifest.json`、目录和 classpath/JAR 资源；独立 ZIP 导入的提问尚未得到答复，
这里采用推荐范围作为工程假设，不记为人类确认。JAR 是 classpath 容器，不能借此提供任意 ZIP 导入。
清单声明包 ID、strict SemVer 包版本、引擎版本范围、资源角色、相对路径、字节长度与 SHA-256。
清单自身、每个资源及累计资源都设预算；拒绝绝对路径、越界 `..`、重复身份、目录符号链接逃逸、
摘要不匹配、不兼容引擎和未列出的 include/import 资源。加载后使用捕获的同一字节参与解析和指纹。
classpath 不写回；可写案例必须位于宿主明确提供的目录。不能把包的只读资源权限当作任意文件写权限。
跨包链接只能经宿主显式注册的解析器，包声明本身不授予网络或文件系统权限。
目录加载默认 `STRICT_HANDLES`，不支持安全句柄的文件系统明确失败，不自动降级。
`TRUSTED_LOCAL` 只能由宿主显式选择，采用合作式目录的身份/摘要检查，
不声称防御同权限恶意进程的并发重命名。

### 2.3 版本与迁移

新的语义版本使用 strict SemVer；兼容范围首版支持明确的比较器交集，不取 latest。
已有 `2025.2`、`2025.3`、`0.1`、`1` 及未版本化方案按原字符串/空值精确绑定，
不自动补位、不重写历史文件。包清单必须明确标出 legacy 版本绑定。
迁移准备一个包含原修订、原/目标方案身份及具体编辑操作的计划；提供预览和差异，
只有显式 apply 才写案例，基准修订变化时拒绝。保留旧方案，迁移后的案例可以重开，
原案例与旧预期仍可独立运行。ESt 迁移示例的独立数值先锁定后实施。

### 2.4 参数有效期与大表

宿主显式给出 effectiveDate；区间为 `[valid-from, valid-until)`，无端点代表无界。
没有隐式“今天”。候选参数集适用于相同方案和键时，重叠或缺档是明确诊断，不能任意挑第一个。
what-if 使用调用者显式选定的参数集并保留来源，不伪称在有效期内。
键控参数由宿主按键选出实际需要的值、出处和版本后交给引擎，不把整张大表注入一个内核值；
这一步只能选择与解码，不能在格式适配器内暗中计算领域结果。

### 2.5 动态 XLSX（M2 延后项）

必须证明真实新增/删除记录后，成员域、关系/父子汇总、期间 prev/首末存量/流量与矩阵均重算。
允许清楚声明容量上限，并采用无宏、无外部连接的兼容公式；超出容量必须显式可见。
仅追加已存在成员的流水、修改旧值或重新导出不满足此项。
生成时审计仍保留快照；记录结构变化及值变化均自动显示过期，恢复原事实可恢复有效状态。
实际 OOXML 表结构、公式和重新打开后的缓存值都验收；POI 与 Excel 行操作差异如实记录。
若探针证明需要 Excel 版本或功能范围取舍，向维护者呈现可复核结果后及时问。

## 4. 独立来源与预算

保留 M0–M3 冻结事实和复算脚本。租赁批量使用原 IFRS 16 独立 Fraction/Decimal 公式，
新增记录只扩展虚构事实；动态表插删的预期先由独立脚本算出，再核对核心和工作簿。
10,000 案例须真的不同 ID、逐值核对、记录编译/会话次数和内存，不重复返回同一个快照。
探针后、最终运行前已冻结批量预算：10,000 个不同案例、1,120,000 次独立数值比对，
总耗时不超过 300 秒，进程堆设为 512 MiB，heap-pool peak 总和不超过 1 GiB；
运行期计划编译与 VALUE_ONLY evidence materialization 为零，所有打开会话均成功关闭。
[M4 历史批量报告](../performance-m4.md)保留 20,875 ms、333,947,640 字节 peak 总和。
[RC.1 冻结验收](../performance-v1.md)实际运行 10,000 个不同案例，完成 1,120,000 次精确比对，
耗时 22,777 ms，heap-pool peak 总和 333,767,296 字节；22 个内核会话全部成功关闭。
初始模板有 22 个计划，560,000 次实际求值；运行期计划编译和 VALUE_ONLY evidence 均为零。
这是一次批量实测，不是多轮分布；390 个常规/期间样本另行独立复核，全部保留并通过原预算。
Combined XLSX 的独立 JFR 实录已完成，详见 M6；不据此解释未复现的 M2 长尾。

公开统计采用实际 API 名称和口径：`CompilationStatistics.syntaxCompilerCalls`、
`semanticCompilerCalls` 是公开编译入口调用次数，不能称为内核私有 cache miss；
`executionPlanCompilations` 按表达式计数，不能把一个模板称为全方案只有一个内核计划。
`CompiledExecutionStatistics` 分别报告打开、关闭尝试、成功关闭，以及公开内核的 row/frame/evidence 计数。
`BatchSummary` 只统计实际交付的当前案例；失败项不能借用 worker 上一成功 `result`。

模板可共享；`CalculationSession`、编译 worker、`CaseGraphRunner` 和 `CalculationReader`
各自在打开线程使用和关闭。增量编辑的 `RecalculationStats.reusedTasks` 是请求前保留的完成任务数，
不是访问命中次数；`executionSessions` 是保留会话数，不是本轮新打开次数。
不可变结果可跨线程；每次公开计算有新 epoch，每次纸面/导出有独立读 epoch，不能每格刷新预算。
